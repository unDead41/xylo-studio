# Xylo Studio UI contract

Source: user's standalone HTML recorder request; Xylophone Music score/timing contract7570da0. No server storage, server authentication, billing, external messages or hardware control. A local export password gate is explicitly a UI restriction, not a server security boundary. Microphone is opt-in, local analysis only; stop/dispose every track on stop, cancel, permission races or hidden page. No raw audio is uploaded or persisted.

V1.03.0 game: Studio and Permainan are separate workspaces. Game settings never replace the Studio take. Entering game stops/cancels Studio transport and finalizes an existing recording; leaving cancels game audio and timers. Same shared synthesizer/AudioContext, disjoint keyboard routing. Pure chart/Run logic is isolated in xylo-game-core, UI/clock in xylo-game-ui; original xylo-core score/export script remains byte-identical.

All 20 catalog variants are available at 75% / 100% / 135% base BPM (integer rounded). Difficulty changes tempo only; judgment windows and health rules are identical. Four UI lanes distribute sorted unique MIDI pitches modulo4 without transposing or replacing any pitch. REST is omitted from tap targets while retaining absolute score time. A tap is an onset, never a hold. Initial countdown is four beats, resume countdown two beats; both outside score time. The arena uses four beats of travel at the selected BPM.

Excellent ≤70ms earns100/+3life; Good ≤150ms earns60/unchanged life. Bonus min(50,floor((combo−1)/10)×10). A pending tile expires once after150ms for−15life; unmatched input costs8life; either resets combo. Initial/maxlife100; life0 fails immediately. Results count actual judgments and unplayed tiles remain pending on failure. Best scores are local and keyed by song/variant/level/BPM/rules-v1. No online competitive integrity or acoustic timing is claimed.

Every run has one AudioContext origin. Paused time is frozen and re-anchored on resume; suspended audio, hidden document or window blur pauses. Start/reset/mode change epochs prevent stale audio promises from starting a cancelled run. Key-repeat/held-key and pointer-ID deduplication prevent repeated inputs. Mouse, multi-touch, native buttons and A S D F are supported. Canvas visual motion is essential gameplay; decorative motion follows reduced-motion rules. Pause remains available. Canvas has an accessible description and real labeled pad buttons; screen-reader-only play has not been acceptance-tested.

Operations: armed recording begins origin at first hit. Stop converts absolute raw timestamps into PPQ24 score; tail note duration is explicit. Tempo edits retime the score, not the raw log. Eight virtual notes C4–C5 by default; changing octave is an explicitly labelled uniform transposition. Quantization preserves collisions for correction, never silently removes notes. Browser scores allow512 events/180s; current Uno C++ remains64 events/30s.10–15s is only the short-preset goal. Manual keys remain eight bars; long scores retain extra pitches, which appear explicitly in the chart/editor and never map to a wrong bar. MIDI0 is a rest and never starts an oscillator.

Presets include four unchanged proposals with base80BPM/end384ticks and six HTML-only arrangements from the remaining video titles. Card BPM/duration come from each score. Additional scores use local IDs129–134, explicit excerpt/transposition notes and no firmware-origin claim; video timestamps remain null. The long catalog adds complete melodic forms or declared verse repeats (38.6–72.8s), plus named section boundaries. Source firmware is null for every long arrangement. A preset replaces current score through Undo; browser retains a separate most recent custom recording. Mouse and physical audio timestamps are labelled separately. Microphone pitch/onset are estimates, reviewed flag remains separate from acoustic verification. C++ export is blocked if microphone guesses are not reviewed or score is invalid. Compatible short C++ exports target xylo::NoteEvent/startScore; long scores exceeding actual Uno limits receive an error. JSON/CSV remain available. No firmware changes, assumed segmentation API, wiring or servo angles.

Autosave: new schema v2 and storage key v2 for compact note data. Read v1 as fallback without overwriting the old key. Preserve manual/edited legacy takes; a restored short preset remains short until the operator selects Long. A failure is surfaced and exports stay available. The core JSON loader validates saved legacy data with schema/size/bounds checks; imported text never becomes HTML/code execution. User removed the Import control in this revision. Dialogs own focus and cancellation. Recording/play/mic modes are mutually exclusive, stale async permission results cannot start a cancelled session. Stop and hidden page cancel scheduled sounds and future callbacks.

Export: both entry points require exactly demo41 or demo@41; incorrect/cancelled submissions produce no data/copy/download. Unlock lasts only while the export dialog is open, or for one quick JSON download. Password fields are cleared on acceptance/cancel, and no unlock/password is persisted. All formats retain existing musical validation.

Timeline: click/Enter/Space on a note calls the same synthesizer with its MIDI pitch, flashes its matching bar and leaves score/raw data untouched. It does not open the editor. Editing stays in Data ketukan. Timeline grows horizontally for long forms and vertically for additional pitches/rests/unknowns, and follows the playback cursor. Unknown notes get a separate lane and explanation; active transport and stale audio requests cannot sound a preview or insert a recording event.


V1.02.0 synchronization: currentEvent indexes the score event, never the pitch value. Playback and timeline audition mark both SVG note and table row with aria-current and a visible ▶ marker. Repeated same-pitch events advance the marker. Only each panel's own scrollbar moves; no page scrollIntoView is used. Lead-in has no active note. Reset clears selection/cursor, stops all pending/active transport, resets scrollbars and Tap history, restores capture_bpm, turns off Metronome, and keeps note edits/raw data.

Tempo is a native40–200 range with a visible numeric output. Input updates existing timing cells/axis labels/summary without rebuilding all rows. A drag creates one Undo snapshot and saves on change. Raw_ms, capture_bpm, tick onsets and durations remain unchanged. During playback the current fractional tick is anchored to AudioContext time, queued future oscillators are cancelled and rescheduled; already sounding voices continue. Event and metronome deadlines remain absolute. Tempo is disabled/guarded during recording or pending playback. C++ and browser duration limits still apply; invalid tempo changes are rejected with the previous value restored. Metronome schedules no beat at or beyond the score end.
